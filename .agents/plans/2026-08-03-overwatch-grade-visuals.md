## Plan

### Goal

Create a separate branch for a large presentation upgrade that pushes Last Line toward a more polished, high-fidelity, hero-shooter style 3D experience while preserving authoritative gameplay. The change must stay in presentation/UI layers unless a documented contract requires otherwise.

### Scope

- Keep `src/game/` untouched by DOM/Babylon concerns.
- Preserve all island/town map authority, movement, combat, LOS, AI, multiplayer protocol, and server semantics.
- Improve real-time visual quality through Babylon scene settings, camera exposure, fog, tone mapping, material response, static visual detail, and HUD presentation.
- Avoid large new downloads or fragile external assets in this pass; use existing assets, procedural detail, and Babylon features.
- Keep quality settings meaningful, with expensive presentation only enabled where safe.

### Acceptance

- The scene should read as a richer 3D battlefield rather than flat procedural boxes: better lighting, atmospheric depth, varied materials, industrial rooftop/facade detail, road and ground visual breakup, and clearer first-person presentation.
- User explicitly raised the bar after the first pass: the final result must aim for an extremely good-looking, as-real-as-possible 3D industrial town scene. Merely adding decorative boxes is not sufficient; browser screenshot inspection must judge whether the result reads as a believable battlefield with material depth, lighting atmosphere, and dense environmental detail.
- The UI should feel more like a modern shooter HUD without adding instructional text or changing control semantics.
- Presentation additions must be non-pickable/non-colliding unless they are existing authoritative geometry.
- Unit/type/build/budget checks must pass or any environment gap must be recorded.
- If browser verification is used, volume must be set to `0`; pages/contexts and local servers must be closed immediately afterward.
- A reviewer must complete naturally before commit/push.

### Corrective Acceptance: Walls, Windows, and Quality Isolation

- Compare the complete feature branch against `origin/main@058988b`, not only the latest uncommitted hunk. Treat any presentation change outside the documented high-quality scope as a regression unless explicitly accepted here.
- Restore `origin/main@058988b` scene lighting, fog, clear color, and image-processing behavior for every map and quality. No quality level may enable the rejected scene-wide ACES/exposure/contrast/vignette color grade; realism remains local geometry/material detail only.
- Low and medium quality must not receive high-quality town visual batches, silhouettes, HUD grade, or enhanced combat effects.
- High-quality town windows must remain real visual openings and must not read as opaque black blockers. The added pane must be non-pickable/non-colliding, light colored, double-sided, and highly transparent (`alpha <= 0.2`).
- Ordinary town walls remain the authoritative procedural wall geometry with `texture.building.wall`; this correction must not replace wall geometry, wall collision, LOS, navigation, or map payloads. The committed white hospital surface behavior remains unchanged.
- High-quality facade weathering must not cover walls with large near-black rectangles. It may use only narrow runoff/rust accents with a lighter material (`alpha <= 0.25`), while the underlying wall texture remains visually dominant.
- Browser acceptance must cover both medium-quality town and high-quality town with volume `0`: both must use the main scene lighting/fog baseline with Babylon image processing disabled; medium must show no high-quality HUD or visual batches; high must show transparent windows and walls without black facade overlays. Capture console errors and clean all browser/server resources immediately after each check.
- Three independent reviewers must inspect: (1) wall/window visual-material behavior, (2) quality isolation across island/town and low/medium/high, and (3) full branch versus `origin/main` for unrelated or incompatible changes. Every blocker/high/medium finding must be fixed and all three reviewers must re-review before commit/push.
